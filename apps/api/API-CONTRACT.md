# ProjectHub API
Base `/api`, JSON, browser credentials included. Cookies are httpOnly; mutations require Origin matching WEB_ORIGIN (default http://localhost:3000). Error shape `{statusCode,message}`.
JSON request bodies are limited to 256 KiB (413 when exceeded); all API responses disable caching. Rate-limit responses use the same JSON error shape with status 429 and standard retry headers. Startup rejects invalid origins, ports, proxy IPs, or cookie-security flags.
Optional request fields may be omitted but cannot be `null`. Human-readable text, email, URLs, and individual technology/team names are trimmed before validation; passwords are preserved exactly. Empty strings clear optional text fields, and an empty screenshot array clears screenshots.
- GET /health -> {ok:true}: process liveness, independent of database availability. GET /health/ready -> {ok:true,database:"up"}: database readiness; returns 503 with a generic message on query failure and is never cached. Neither endpoint requires authentication.
- POST /auth/signup {name,email,password,department,semester}; POST /auth/login {email,password}; POST /auth/logout; GET /auth/me -> user object (401 logged out).
  Logout is idempotent and clears the session cookie even when the session is missing, expired, or already revoked. `COOKIE_SECURE=true` enables secure cookies in every environment; production defaults to secure cookies.
  Sessions last seven days. Each user can hold up to ten active sessions; signing in removes that user's expired sessions and evicts the oldest excess sessions. Concurrent sign-ins are serialized per user when enforcing the cap.
- PATCH /profile {name?,department?,semester?,bio?} -> user.
- GET /projects?q=&department=&semester=&type=&tech=&page=1&limit=12&sort=recent|popular -> {items,total,page,limit,pages}. Approved only.
  Query values must be single strings (repeated/structured values and unsupported parameter names return 400). Page is an integer 1–10000; limit is 1–48; semester is 1–12. Out-of-range or malformed numbers and unknown sort values return 400. Search is at most 200 characters, department 80, type 60, technology 40. Empty text filters are ignored. Recent/popular sorts have deterministic timestamp/ID tie-breakers.
- GET /projects/:id -> project; POST /projects/:id/view -> {views}; GET /my/projects -> project[]; GET /my/bookmarks -> project[].
- POST /projects {title,description,department,semester,type,techStack:string[],teamMembers:string[],githubUrl?,demoUrl?,screenshots?:string[]} -> project with version 0 and DRAFT status. Create does not accept expectedVersion.
- PATCH /projects/:id requires the same project fields plus `expectedVersion` -> updated project. Editing approved/pending work resets it to draft.
- DELETE /projects/:id requires a JSON body `{expectedVersion}` -> {ok:true}.
- POST /projects/:id/submit requires a JSON body `{expectedVersion}` -> project (PENDING).
  Compatibility requirement: every existing-project edit, submission, deletion, and moderation request must supply `expectedVersion`, an integer from 0 to 2147483647 copied from the project snapshot the user edited or reviewed. Missing/invalid values return 400. Stale values or overlapping write conflicts return 409 without overwriting content or adding a moderation audit entry. Clients must retain unsaved work and explicitly reload/review before retrying; they must not automatically substitute the latest version.
  Successful content/workflow mutations increment the response's monotonic `version`. When saving then submitting, use the save response's version for submission. Views, likes, and bookmarks do not change the version or require expectedVersion.
- POST /uploads multipart field `file` -> {url}; PNG/JPEG/WebP up to 5 MB, authenticated. Use returned URL in screenshots.
  Exactly one file part and no extra form fields are accepted. At most two uploads are parsed/processed concurrently per API process; excess requests return 503 and `Retry-After: 1`. Files are removed if recording ownership fails. Missing stored image files return 404.
- PUT /projects/:id/like and DELETE /projects/:id/like; PUT /projects/:id/bookmark and DELETE /projects/:id/bookmark -> {liked,bookmarked,likes}.
- GET /moderation/projects?status=PENDING -> project[] (faculty/admin); PATCH /moderation/projects/:id {status:APPROVED|CHANGES_REQUESTED|HIDDEN,feedback?:string,expectedVersion:number}.
  Unsubmitted drafts cannot be moderated. Approval requires PENDING; requesting changes requires nonblank feedback and may reopen hidden or published work. Successful moderation and its audit entry commit atomically.
- GET /admin/users -> user[]; PATCH /admin/users/:id/role {role:STUDENT|FACULTY|ADMIN}; GET /admin/audit -> audit[]. Admin only.
Project fields: id,title,description,department,semester(integer1-12),type(string),techStack,teamMembers,githubUrl,demoUrl,screenshots,status,feedback,views,version(number),createdAt,updatedAt,ownerId,owner:{id,name,department,semester,bio},likes(number),bookmarks(number),liked(boolean),bookmarked(boolean). Public results never expose owner email. Auth/profile user includes id,name,email,role,department,semester,bio,createdAt.
